# P3-T07 — Packed layout + canvas overview renderer (QA-018)

## Context

QA-018 (Medium, open since Cowork round 12): GitLab (992 tables) lays out at 3,904 × 242,359 px, so
Reset view at the 0.05 zoom floor shows a thin slice, and PNG export is unreadable. A packing pass
was prototyped in P2-T10 (GitLab → 24,696 × 15,892 px, small schemas byte-identical), but it put
1,790–2,000 DOM tables in the fitted view of `neighbourhood-2000` (select/deselect 150–330 ms,
panning 10–17 fps). ADR-023 decided that packing ships only together with a cheap overview renderer.
This task delivers both. Outcome: large shallow schemas fit a sane aspect ratio, and the
zoomed-out view of big schemas is drawn on one `<canvas>`, so it stays fast.

User decisions (this session): **keep existing saved layouts** (packing applies to fresh layouts and
the Layout button; no key bump); **canvas overview only for schemas with ≥ 300 tables** below zoom
0.3 (80–299 tables keep today's DOM skeleton rows).

First implementation step: copy this plan to `docs/development/plans/p3-t07.md`.

Cowork plan review (2026-11-20): **approved with changes 1–8**, folded in below and marked
**[R1]…[R8]**.

## Workstream A — Packed layout (pure, `src/graph`)

New `src/graph/layout-packed.ts` → `layoutPacked(schema, options): DagreLayoutResult`, called from
`computeLayout` in `src/stores/layout-store.ts:40-57` instead of `layoutWithDagre` directly.

1. Run `layoutWithDagre` on the whole schema (unchanged code path). Compute its bounds. If the
   layout is not too elongated (`max(w,h) / min(w,h) ≤ PACK_ASPECT_LIMIT` (4), or fewer than
   `PACK_MIN_TABLES` (50)), return it unchanged → small and normal schemas stay byte-identical.
   (Cost: one extra full Dagre run only for elongated schemas; check GitLab's real-fixtures perf
   test (< 7.5 s) still passes. If not, skip the full run when components/isolated count already
   predict packing.)
2. Otherwise: split into weakly connected components (ignore self-references; reuse adjacency
   style from `src/domain/schema/selectors.ts` `getAdjacency` only if it is pure-graph friendly,
   else a small union-find here).
3. Each multi-table component → `layoutWithDagre` on a sub-schema (same options). If its extent
   along the rank-stacking axis exceeds `LANE_LIMIT` (e.g. 6,000 px), wrap tall ranks: group
   positions by rank coordinate, split a too-tall rank into `ceil(h / LANE_LIMIT)` sub-columns
   (keep original order), shift later ranks outward by the added width. Drop that component's
   `edgeRoutes` when wrapping happened (edges fall back to the default path).
4. Isolated tables → a grid block (sorted by `tableOrder`).
5. Shelf-pack component boxes (height desc, ties by first `tableOrder` index for determinism) into
   rows targeting a 16:10 overall aspect, with a `COMPONENT_GAP`. Offset positions and route
   waypoints/`sourceAt`/`targetAt` by each block's offset.
6. Direction-generic: LR wraps by height, TB by width (axis swap helper), even though no UI exposes TB.

Tests `src/graph/layout-packed.test.ts`: small sample and 12-table sample byte-identical to Dagre;
deterministic (two runs, and a run on a re-parsed schema, produce identical positions, so the
fingerprint-keyed saved layout stays stable **[R7]**); no overlaps (GitLab-like synthetic: one hub with 250 children + 130 isolated);
aspect within [1/3, 3] for that shape; every table positioned; routes offset correctly / dropped
after wrap; TB variant. GitLab bounds asserted in `real-fixtures-performance.test.ts` (aspect ≤ 3,
time budget kept).

## Workstream B — Canvas overview renderer

Active when `tables ≥ OVERVIEW_TABLES` (300) and the zoom is low, **with hysteresis [R2]**: enter
below `OVERVIEW_ENTER_ZOOM` 0.28, leave above `OVERVIEW_LEAVE_ZOOM` 0.32, keep the current state in
between. Add `canvasOverview` to `ui-store` next to `canvasZoomedOut` (which keeps its plain 0.3
rule for 80–299 table skeleton rows). A small pure helper `nextOverviewState(prev, zoom, tables)`
holds the rule and is unit-tested. The canvas root always carries `data-overview="true|false"`
**[R6]**.

1. **Shared geometry (pure) [R3].** Extract the inline geometry from
   `src/generators/diagram-svg.ts:206-225` into `src/generators/diagram-geometry.ts`
   (`diagramGeometry(schema, layout) → { tables: {id, x, y, w, h}[], edges: {id, from, to, d}[] }`,
   using `computeDiagramBounds`, `NODE_WIDTH`, `estimateNodeHeight(visibleColumns(table,
   collapsed[id]))`, `edgePath`). Heights follow the per-table collapse state (full / keys-only /
   header) exactly as export does. `renderDiagramSvg`, the overview drawing and the overview
   hit-test all use these same rects. `renderDiagramSvg` output must stay byte-identical (its
   tests stay green).
2. **Decide before mounting [R1].** The overview state is decided from the *target* zoom before
   nodes are first handed to React Flow, so GitLab never mounts ~992 DOM tables just to hide them:
   - First paint / import: compute the fit zoom from `computeDiagramBounds` + the canvas size,
     with the same padding 0.15 and maxZoom 1 as `FIT_VIEW_OPTIONS`, in a pure
     `fitZoom(bounds, size, padding)`. Session restore uses `pendingViewport.zoom`. The initial
     `nodes`/`edges` state (`schema-canvas.tsx:84-92`, and the `syncedBase` reset) is built
     already `hidden` when the overview will be active.
   - Reset view / Controls fit: compute the target zoom first; if it enters the overview, flip
     `canvasOverview` (hiding nodes) before the animated `fitView`.
   - Zoom-driven changes (wheel, pinch, centring) go through `ZoomDetail`'s transform
     subscription with the hysteresis above.
3. **Hide DOM while in overview.** When `canvasOverview` flips, map nodes and edges to
   `hidden: true` (and back) in local React Flow state only. React Flow keeps them in its lookup,
   so positions and selection survive and nothing mounts. Fit, Reset view, Controls and
   centre-on-table use `includeHiddenNodes: true`.
   - **View-only [R5]:** `hidden` never reaches `layout-store`, the saved layout, the session record
     or any generator. `onNodesChange` ignores the visibility changes for persistence. Export
     reads from the stores, not from React Flow state; a test asserts that PNG/SVG/text export
     output is byte-identical with the overview on and off at the same layout.
   - **Focus [R4]:** before hiding, if `document.activeElement` is inside a `.react-flow__node` or
     `.react-flow__edge`, move focus to the React Flow pane (`.react-flow__pane` / the canvas root
     made focusable with `tabIndex=-1`, same target as the BB-P2 focus rule), never BODY. Hidden
     nodes are unmounted, so Tab cannot reach them. Search / table-list "centre on table" works
     in the overview (includeHiddenNodes); if the target zoom stays in the overview, the selection
     outline is drawn on the canvas.
4. **MiniMap [R8].** Check whether React Flow's MiniMap drops `hidden` nodes. If it does, render
   the MiniMap from a `nodeComponent`/custom path that draws from `diagramGeometry` (or pass
   the hidden flag only to the main view via a separate visible-nodes prop if the API allows). A
   blank minimap at the fitted GitLab view is a regression, not accepted. Only if no fix works:
   known issue in the handoff, with a description of what the minimap shows.
5. **`OverviewLayer` component** (`src/components/canvas/overview-layer.tsx`): a full-size
   `<canvas aria-hidden>` rendered inside `<ReactFlow>` below the viewport, `pointer-events: none`,
   DPR-aware. Builds world-space `Path2D`s once per `base` (tables batched into one path per
   style, edges into dimmed / undimmed paths); on each transform change (RF `useStore` transform,
   coalesced with `requestAnimationFrame`) calls `setTransform` and fills/strokes. Colours from CSS
   tokens via `getComputedStyle` (re-read on theme change; reuse `src/lib/export-palette.ts` if it
   already reads them). Draws: table body + header strip, table name when it would be ≥ 6 px on
   screen, edges, selected table outlined, focus set (`ui-store.focusSet`) full opacity and others
   at the `--dim-node` / `--dim-edge` values. Verification hooks on the canvas element **[R6]**:
   `data-testid="canvas-overview"`, `data-tables-drawn`, `data-edges-drawn`, `data-selected-id`
   (empty when nothing is selected), updated on each draw.
6. **Interaction.** `onPaneClick` in overview: `screenToFlowPosition` → hit-test table rects
   (simple linear scan or a coarse grid built with the paths) → `selectTable(id)` or `null`.
   Pointer cursor not needed. Keyboard path stays the table list (Enter centres a table; if the
   zoom stays below 0.3 the selection shows on the canvas). Panning/zooming stays React Flow's.
7. Accessibility: the canvas is decorative (`aria-hidden`); add a visually hidden status
   "Overview: N tables drawn as a picture; zoom in or use the table list" via the existing
   pattern.

Tests: `diagram-geometry.test.ts` (keys-only / header heights match `estimateNodeHeight`);
`overview-layer.test.tsx` (jsdom: canvas mounted only when active; data hooks; hit-test unit-tested
as a pure function `hitTable(geometry, point)`); `nextOverviewState` and `fitZoom` unit tests
(hysteresis band, restore zoom); `schema-canvas` tests: initial nodes already hidden when the fit
zoom enters the overview, focus moves to the pane on hide, `hidden` never reaches `layout-store`;
export byte-identity test (overview on/off); `zoom-detail.test.tsx` extended.

## Acceptance criteria (draft)

- AC-P3-T07-1 GitLab fresh import: layout aspect ≤ 3:1 either way, no overlaps; Reset view shows
  the whole diagram.
- AC-P3-T07-2 Schemas below the packing trigger (12-table sample, Sakila, mysqldump-180) lay out
  exactly as before.
- AC-P3-T07-3 ≥ 300 tables in the overview (enter < 0.28, leave > 0.32): one canvas, no DOM table
  nodes, and at most a handful of DOM nodes ever mounted before it appears on import / restore;
  zooming in restores DOM nodes at the same positions and heights (collapse state included).
- AC-P3-T07-4 Click a table in the overview selects it (inspector, dimming drawn); pane click
  clears; table-list centring works in the overview; focus never drops to BODY when nodes hide.
- AC-P3-T07-5 `neighbourhood-2000` fitted view: hub select/deselect ≤ 40 ms first frame, panning
  ≥ 45 fps on the M1 harness (record actual numbers either way).
- AC-P3-T07-6 Saved layouts are kept on reload/restore; the Layout button produces the packed
  layout and saves it; packing is deterministic.
- AC-P3-T07-7 Light/dark colours match the DOM canvas tokens; PNG/SVG export of GitLab uses the
  packed positions; export output is byte-identical with the overview on or off.
- AC-P3-T07-8 The MiniMap still shows tables while the overview is active (or a documented known
  issue if impossible).
