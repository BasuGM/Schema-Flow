# P4-T06 — Accessibility audit & docs (plan)

Saved to `docs/development/plans/p4-t06.md` as the first implementation step.

## Context

ROADMAP Now → Next is P4-T06, then DEPLOY-01 and DOC-01. DOC-01 needs its results for the
accessibility part of FEATURES. The backlog has only QA-041/042, both fixed and waiting for QA,
so nothing blocks this task.

What exists today: a lot of accessibility work built by hand. Panels are labelled `aside`s, the
canvas is `main`, nodes can be reached with Tab and have names, dialogs return focus, the
combobox follows WAI-ARIA, there is a global reduced-motion rule, and the jsx-a11y lint rules
are on.

What is missing:
- No automated audit. Contrast has only been checked by hand (AC-P1-T09-5).
- No `ariaLabelConfig`, so React Flow's built-in English strings are used as they are.
- No skip link.
- Accessibility is not documented in one place.
- Known gaps that are accepted: edges can't be reached with the keyboard, and reduced motion is
  covered only by a unit test.

Goal: add an automated axe audit of everyday screens, fix the real violations at their root
cause, and write one honest accessibility section. This is not an aim for full WCAG
conformance (Scope rules).

## Workstreams

### WS-A — Automated axe audit (e2e)

- **Dependency:** add `@axe-core/playwright` as a dev dependency, at an exact version that is at
  least two weeks old. Justify it in ARCHITECTURE first. `axe-core` is already installed, but
  only because `eslint-plugin-jsx-a11y` pulls it in, so we can't rely on it staying.
- **New spec `tests/e2e/a11y.spec.ts`:** uses the helpers in `tests/e2e/support/app.ts`
  (`openSample`, `clickTable`, …). Rules: tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`.
- **States checked:** each one in light and dark. The matrix follows the pattern in
  `bug-bash.spec.ts:78`.
  1. Empty start screen
  2. Sample loaded, nothing selected
  3. Table selected, inspector on Columns, then Relations, then Path
  4. Search dialog
  5. Import dialog
  6. Export dialog
  7. Shortcuts dialog
  8. Issues panel
  9. Health panel
  10. Phone 390×844 with a table-list sheet open
- **Assertion:** zero violations. On failure, print only rule id, impact, target and count
  (compact output).
- **Exclusions:** only with a comment in the spec and a line in ADR-038. Expected candidate:
  React Flow attribution, if it is shown. No blanket rule disables.

### WS-B — Fix the violations found

- Run WS-A first, then fix the violations at their root cause in components or theme tokens.
  Likely candidates are contrast of muted text and PK/FK tokens in `src/app/globals.css`,
  missing names, and nested-interactive or duplicate landmarks.
- Each fix gets a colocated unit test where it can be tested in jsdom. Contrast fixes are
  covered by the axe spec.
- If WS-A finds more than about 10 distinct rule failures, fix the High/serious ones here. Log
  the rest in the QA_LOG Backlog as Deferred → phase-end bug-bash. This follows the triage rule.

### WS-C — Small known-gap fixes

- **Skip link:** add "Skip to diagram" as the first focusable element, shown on focus, pointing
  at `main` in `canvas-area.tsx` (`tabIndex={-1}` target). Add a `data-testid="skip-link"` and a
  unit test.
- **`ariaLabelConfig`:** set it on `<ReactFlow>` in `src/components/canvas/schema-canvas.tsx`,
  module-scope constant, with SchemaFlow wording for the controls, minimap and node
  descriptions. Leave the edge labels as they are.
- **Edges:** keep `edgesFocusable={false}`. Document that the Relations tab and the Path tab are
  the keyboard equivalent. Making edges focusable is not done (scope).

### WS-D — Docs

- **README:** add an "Accessibility" section of 10–15 lines. Contents:
  - keyboard model (Tab through the UI and nodes, Enter/Space selects, `?` lists shortcuts,
    skip link)
  - screen reader names
  - reduced motion
  - light/dark contrast checked by the axe suite (with a stamp)
  - known limitations: edges, the canvas spatial layout, reduced motion not verified in a
    browser
- **AGENT-REFERENCE:** add the a11y spec to the "Browser suite" section and `skip-link` to the
  testid list.
- **VERIFICATION:** add AC-P4-T06-1…6:
  1. axe spec green in light and dark
  2. skip link
  3. ariaLabelConfig wording
  4. README section
  5. no regression in `bug-bash.spec.ts` focus tests
  6. phone toolbar PASS
- **ADR-038 "Accessibility audit with axe":** tags, states, exclusions, edges decision. Add a
  Decision index line.

- `npm run check` green.
- Run `scripts/cleanup.sh`, check `uptime` load < 4, `npm run build && npm run start`, then
  `npm run e2e`. The full suite must be green, including `a11y.spec.ts` with 0 violations or only
  the documented exclusions.
- `scripts/headless/toolbar-width.mjs` prints PASS at 390×844.
- Handoff `P4-T06.md` with actual counts, ROADMAP Now updated, status **Awaiting Cowork
  verification**, and QA_LOG reading "Pending — not independently verified". Commit
  `P4-T06: accessibility audit & docs` per workstream, then push.
