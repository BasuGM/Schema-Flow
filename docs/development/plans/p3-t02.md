# P3-T02 — Per-table collapse modes UI

## Context

`CollapseMode = "full" | "keys" | "header"` already exists end to end, but users can't set it:
- `DiagramLayout.collapsed` ([src/domain/schema/types.ts:135,164](src/domain/schema/types.ts)), validated and persisted per fingerprint ([src/stores/layout-persistence.ts](src/stores/layout-persistence.ts), ADR-025).
- `visibleColumns` / `renderedColumns` / `estimateNodeHeight` ([src/graph/node-metrics.ts](src/graph/node-metrics.ts)); dagre sizes nodes by mode; hidden columns fall back to header handles ([src/graph/handles.ts](src/graph/handles.ts)); a highlighted column is still shown (ADR-016).
- `SchemaCanvas` already rebuilds nodes when `collapsed` changes ([schema-canvas.tsx:64-81](src/components/canvas/schema-canvas.tsx)).

The missing parts are the store actions and the UI. Scope (user choice): an inspector control, a canvas node-header toggle, and a bulk "all tables" action.

## Workstream A — store actions (layout-store)

[src/stores/layout-store.ts](src/stores/layout-store.ts):
- `setCollapse(fingerprint, tableId, mode)`: no-op if unchanged. Store `"full"` by **deleting** the key so the map stays sparse. Drop edge routes touching the table with the existing `dropRoutesAt(edgeRoutes, positions[tableId])` ([src/graph/edge-path.ts:102](src/graph/edge-path.ts)), as `setPosition` does, because the handle offsets change. Do **not** bump `version` or re-run layout: positions stay where the user put them, and the canvas rebuilds through the `collapsed` dependency. Then `save(fingerprint)`.
- `setAllCollapse(fingerprint, mode)`: `collapsed = {}` for full, or every table id → mode. Drop all `edgeRoutes` (routes stay undefined, and edges use their default paths). Save.
- Expanding can make a node overlap the one below it. That's accepted and documented; **Layout** re-packs using the current modes (computeLayout already passes `collapsed`).
- Tests (`layout-store.test.ts`, extend or create): sparse map, routes dropped only for that table, no `version` bump, persisted payload round-trips through `loadLayout`, unknown fingerprint is a no-op.

## Workstream B — inspector control

- New `src/components/inspector/collapse-mode-control.tsx`: a labelled `role="radiogroup"` ("Show on canvas"), made of three native radio inputs styled as a segmented control: **All columns · Keys · Header only**. Arrow keys come free from native radios, with a visible focus ring on the label (`has-[:focus-visible]:ring-2`, which avoids the QA-029 class of bug). `data-testid="inspector-collapse-{full|keys|header}"`. It reads the mode with a narrow selector `s.layouts[fp]?.collapsed[tableId] ?? "full"`.
- Place it in [inspector.tsx](src/components/inspector/inspector.tsx) between the header block and the counts `<dl>`.
- jsdom test: selecting Keys updates the store; the current mode is checked; keyboard arrow changes it.

## Workstream C — canvas node toggle

[src/components/canvas/table-node.tsx](src/components/canvas/table-node.tsx): a small ghost icon button in the header, after the column count, that cycles full → keys → header → full. The icon is `ChevronsDownUp` / `ChevronsUpDown` / `ChevronRight` by mode. `aria-label="Collapse mode: Keys (click to change)"`, `tabIndex={-1}` (the keyboard path is the inspector, so we don't add 2,000 tab stops), `className="nodrag nopan"`, and `stopPropagation` so clicking it doesn't select or drag the node. Hidden when `skeleton` (zoomed out), like the icon. `data-testid="node-collapse-toggle"`.
- `data.mode` already comes in via props. The click calls `useLayoutStore.getState().setCollapse(...)` with the fingerprint from `useSchemaStore.getState()`, so no new subscriptions per node (perf).
- Extend `table-node.test.tsx`: the button cycles modes and doesn't change selection; it's absent in skeleton mode.

## Workstream D — bulk action

- New `src/components/workspace/collapse-all-items.tsx`: a shared fragment, the same pattern as `NeighbourhoodRadio`. A `DropdownMenuLabel` "All tables" plus three `DropdownMenuItem`s: "Show all columns", "Keys only", "Headers only". These are actions, not radios, since mixed per-table state has no single value. Disabled without a schema. testIds `{prefix}-collapse-all-{mode}`.
- Add it to [settings-menu.tsx](src/components/workspace/settings-menu.tsx) and [more-menu.tsx](src/components/workspace/more-menu.tsx). No new toolbar button, so the phone toolbar width is unchanged (still run `scripts/headless/toolbar-width.mjs`).
- Test in `more-menu.test.tsx` (or a new test): an item sets every table's mode.

## Workstream E — e2e + docs

- Playwright `tests/e2e/collapse.spec.ts`: load a sample, select a table, choose Keys. The node shows only PK/FK rows. Reload, and the mode persists. Use the node toggle, then "Headers only" from Settings; edges still render (header handles).
