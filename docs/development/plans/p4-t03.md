## Context

ROADMAP Now → Next is P4-T03 "Subject-area grouping/filtering" (title only). P4-T02 is Verified with
known issues (round 26, `d4903f8`); Backlog has 1 open item, QA-041 (Low, deferred to the next P4 bug-fix).
Goal: in a 100–300-table schema the user can see the tables grouped by subject area and hide whole
areas on the canvas to work on one part at a time.

User decisions (2026-11-23):
- **Areas are auto-derived**, not editable. Source rule (pure, deterministic):
  1. If the tables have **2+ distinct schema names** (missing counts as the default) → area = schema
     name (`displayTableName` rules: default shown as `public` on PostgreSQL, `(default)` otherwise).
     saas-300 → core / billing / analytics.
  2. Otherwise → area = lower-cased **name prefix before the first `_`**; prefixes with fewer than
     3 tables, and names without `_`, go to **Other**. mysqldump-180 → 9 areas × 20.
  3. If that gives fewer than 2 real areas → **no areas**: the list stays flat, nothing changes
     (ecommerce, sakila, blog).
  Areas are ordered by first appearance in `tableOrder`; Other is last.
- **Filtering hides, positions stay**: unchecked areas' tables and every edge touching them get React
  Flow `hidden: true`; no relayout, stored positions untouched. Hidden state lives in `ui-store`,
  is reset by a new schema and is **not persisted** (a reload shows everything), like `activePath`.

ADR-036 records both.

## Design

- **Pure module** `src/analysis/subject-areas.ts`: `getSubjectAreas(schema): SubjectAreas | null`
  returning `{ source: "schema" | "prefix", areas: { id, label, tableIds }[], areaOf: Map<TableId, id> }`,
  memoised per schema object (WeakMap, as other selectors do). Reuses `showsSchemaName`.
- **ui-store**: `hiddenAreas: ReadonlySet<string>` (empty = all shown); actions `setAreaVisible(id, visible)`,
  `showOnlyArea(id)`, `showAllAreas()`; cleared in the new-schema reset block next to `activePath`.
- **Canvas** (`schema-canvas.tsx`): a `useMemo` over `base` + `hiddenAreas` computes the hidden node
  and edge sets; `setNodes`/`setEdges` map `hidden` (keeps drag state; same pattern as the base sync).
  Reset view and the minimap then ignore hidden nodes (React Flow's default `includeHiddenNodes: false`).
- **Auto-unhide** (`use-area-filter-sync.ts`, next to `use-focus-set-sync.ts`): a store subscription on
  `focusRequest` and `fitRequest` turns back on the area of any requested table that is hidden. This
  covers list clicks, search, Health/Issues "Show table", inspector links and path "Show on canvas"
  without touching each caller.
- **Table list** (`table-list.tsx`, also the phone sheet): when areas exist,
  - an **Areas** disclosure under the filter field: "Areas · 2 of 3 shown", expanding to one row per
    area: checkbox (label = area name, count), an "Only" button, and "Show all" at the top;
  - the list is **grouped** under small area headers (name + count) in area order; the text filter
    still applies inside groups, empty groups are not shown;
  - tables in hidden areas stay listed, muted, with an eye-off icon (`aria-label="hidden on canvas"`);
    clicking one reveals it (auto-unhide).
  Without areas the list is exactly as today.
- **Canvas notice**: while any area is hidden, a small pill at the top-left of the canvas
  "N tables hidden · Show all" (`area-filter-notice`, button `area-show-all`), so the state is visible
  with the list closed (phone).
- **Unchanged on purpose**: image/SQL/Prisma export render from the schema and include all tables;
  neighbourhood dimming and path highlight work on the visible tables; Health/Issues list everything.
