## A — Inspector focus anchor (QA-027, QA-028)

Decision (ADR-032): after in-inspector navigation that unmounts the activated control, focus moves to
the inspector title `<h2 data-testid="inspector-title">`, which persists across selection changes
and announces the new table name to screen readers.

- `inspector.tsx`: give the title `tabIndex={-1}` and a visible focus style
  (`rounded-sm outline-none focus-visible:ring-2 focus-visible:ring-ring`, matching the Back button).
- New `src/components/inspector/focus-inspector.ts`: `focusInInspector(from: HTMLElement, testId)`
  — captures `from.closest('[data-testid="inspector"]')` at click time; inside
  `requestAnimationFrame` it looks up `[data-testid=testId]` in that container, or, if the container
  is no longer connected (`isConnected === false`), in the first connected
  `[data-testid="inspector"]` on the page, so focus never falls to `body` (review amendment 1).
  Reuse it for the existing QA-026 helper `clearSelectionKeepingFocus` (target `inspector-empty`) so
  all three share one mechanism.
- Mouse clicks use the same path: focus still moves to the title, but `:focus-visible` stays false
  (the browser's heuristic after a pointer interaction), so no stray ring (amendment 4).
- `relations-tab.tsx` `RelationRow` onClick: `navigateToRelated(...)` then
  `focusInInspector(e.currentTarget, "inspector-title")`.
- `inspector.tsx` Back onClick: `inspectorGoBack()` then the same.
- Store functions in `src/stores/reveal.ts` stay DOM-free (search/table list also call `revealTable`
  and must not steal focus).
- Unit tests in `inspector.test.tsx` (jsdom; flush rAF with fake timers or `waitFor`): after clicking a
  relation target, `document.activeElement` is `inspector-title` with the new table name; same after
  Back; QA-026 test still passes; one test for the fallback (container removed before the rAF fires
  → the connected inspector's target is focused).

## B — Import file-label ring (QA-029)

- `import-source.tsx` label: `has-focus-visible:` variants (built into Tailwind v4) of exactly the
  ring classes in `src/components/ui/button.tsx`'s base `focus-visible:` set (`border-ring`, `ring-3`,
  `ring-ring/50`), copied from that file rather than retyped (amendment 2). `has-focus-visible`
  rather than `:focus-within`, so a mouse click shows no ring.
- Unit test: the label carries the `has-focus-visible:` classes (jsdom can't compute `:has`); the
  real ring is checked in e2e (C).
