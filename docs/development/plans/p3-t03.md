# P3-T03 — Image export (PNG / SVG)

## Context

Next task per the ROADMAP Now block: P3-T03. Backlog has 4 open items (QA-018 → P3-T07, QA-027…029 → P3-T08); none block this task, and this task doesn't touch the inspector or import dialog, so P3-T08 stays separate.

The roadmap said "via `html-to-image`". **User decision (this session): draw our own SVG instead.** The canvas mounts only visible nodes above 80 tables (`onlyRenderVisibleElements`) and draws skeleton rows when zoomed out (`ZoomDetail`, ADR-023), so a DOM snapshot would miss most of a large schema (GitLab: 992 tables, ~242,000 px tall). Node geometry is fixed (`NODE_WIDTH` 280, header 40, row 26, padding 6 in [src/graph/node-metrics.ts](src/graph/node-metrics.ts)) and fonts are system stacks, so a pure-TS renderer can reproduce the diagram closely with no dependency. PNG = that SVG rasterized on a canvas.

**UI (user decision):** a small "Export image…" dialog opened from the Settings and More menus. Options: format PNG/SVG, theme Current/Light/Dark, PNG scale 1×/2×, a size line, and Download. P3-T05 can fold it in as a tab later. No new toolbar button.

## Workstream A — pure SVG generator (`src/generators/`, no React/DOM)

`src/generators/diagram-svg.ts`:
- `renderDiagramSvg({ schema, layout, palette, measure }) → { svg, width, height }`.
- Tables: iterate `schema.tableOrder`. Position from `layout.positions`. Mode from `layout.collapsed[id] ?? "full"`. Rows from `visibleColumns(table, mode)`: the export ignores search highlight, selection and dimming. Height from `estimateNodeHeight`. Draw a rounded card (card fill, border stroke), a header band (muted), the title via `displayTableName` (semibold sans 14), and the column count ("n" or "shown / total"). Each row has a PK row tint, a PK/FK glyph (small circle/key-ish shape or "PK"/"FK" text in pk/fk colour; no lucide), the name (semibold if PK), and right-aligned mono 11 `dataType.raw` plus "null". Text uses ellipsis truncation through the injected `measure(text, font)`, with a binary search over length.
- Edges are drawn before the tables, as React Flow does. Endpoints mirror `schemaToFlow` and the handles. Source is the FK table's left edge at the row centre (`rowCenterOffset`) of `from.columnIds[0]` if visible, otherwise the header centre. Target is the referenced table's right edge, the same way. Match the handle offset in `globals.css` `.column-handle`. Path: reuse `routeSegments` / `segmentsToPath` ([src/graph/edge-path.ts](src/graph/edge-path.ts)) with the stored route only when `samePosition` holds for both ends. Self-reference uses the same loop as `edgePath` in [relationship-edge.tsx:147](src/components/canvas/relationship-edge.tsx). Move that small `edgePath` helper into `src/graph/edge-path.ts` and use it from both places (no duplication). Cardinality "N"/"1" text matches `CardinalityMarker` offsets. Stroke 1.25 in the edge colour.
- Bounds: min/max over the nodes plus 40 px padding, so the viewBox starts at the content origin. Background rect in the canvas colour (no dot grid). Root `<svg xmlns width height viewBox role="img" aria-label>` + `<title>` (schema name). `font-family` uses the same stacks as `--font-sans` / `--font-mono`.
- XML-escape every user string (`& < > " '`). Add `data-table-id` / `data-relationship-id` on the groups (for tests / e2e).
- `ExportPalette` type plus `DEFAULT_LIGHT_PALETTE` / `DEFAULT_DARK_PALETTE` hex constants (fallback + tests).
- `approxMeasure(text, font)`: a char-width estimate, the default for tests and the fallback.

`src/generators/raster-size.ts`: `rasterSize(w, h, requestedScale) → { scale, pxWidth, pxHeight, reduced }`, clamped to `MAX_SIDE = 16384` and `MAX_AREA = 8192²`. Also `exportFileName(schemaName, ext)`: slugified, fallback `schema`.

Tests (colocated): table and edge counts, sparse collapse modes (keys / header → header endpoints), valid vs stale route, self-reference, bounds/padding, escaping (`a<b&"c"`), truncation, deterministic output, raster clamp cases (small, 2×, GitLab-size → reduced), file names.

## Workstream B — browser adapters (`src/lib/`)

- `src/lib/export-palette.ts`: `resolveExportPalette(theme: "light" | "dark")`. Mount a hidden element (with or without `.dark`), read each token (`--canvas`, `--card`, `--card-foreground`, `--muted`, `--muted-foreground`, `--border`, `--edge`, `--brand`, `--pk`, `--fk`), and convert the oklch colours to `#rrggbb` / `rgba()` by painting a 1×1 canvas and reading `getImageData`. If no canvas is available (jsdom) or anything fails, fall back to the default palette. "Current" maps to `resolvedTheme` from next-themes.
- `src/lib/measure-text.ts`: a canvas `measureText` with a cached context; falls back to `approxMeasure`.
- `src/lib/svg-to-png.ts`: `svgToPngBlob(svg, w, h, scale)`. Blob URL → `Image.decode()` → canvas `drawImage` → `toBlob`. Returns `{ ok, blob } | { ok: false, message }` and never throws. Revokes the URL.
- `src/lib/download.ts`: `downloadBlob(blob, filename)` via an `<a download>`, revoking the URL on the next tick. P3-T05 reuses it.

## Amendments (approved with changes)

1. **One size source:** `computeDiagramBounds(schema, layout)` exported from `src/generators`, used by both `renderDiagramSvg` and the dialog size line. `rasterSize` defines rounding once (`Math.round`). e2e (b) also checks that 2× equals 2 × the size line (±1 px).
2. **Area cap:** `MAX_AREA = 16_777_216` (4096²); `MAX_SIDE` stays 16384. Test a wide-but-short layout that hits the area cap and not the side cap.
3. **XML safety:** besides `& < > " '`, strip XML 1.0-invalid characters (U+0000–U+0008, U+000B, U+000C, U+000E–U+001F, lone surrogates) from every user string, including `<title>` and `aria-label`. Test: a name containing `\u0001` gives SVG that DOMParser parses without `<parsererror>` (jsdom), and the PNG path decodes it in e2e.
4. **downloadBlob:** revoke the object URL after `setTimeout` ~10 s, not on the next tick.
5. **Positions:** use the positions the canvas renders (saved layout or auto-layout). If a table has no position, the generator places it deterministically (or skips it with a warning) and never produces NaN. With 0 tables the menu item is disabled and the generator returns a valid empty SVG. Unit tests for both.
6. **Focus:** use `onCloseAutoFocus` / an explicit trigger ref so focus returns to `toolbar-settings` or `toolbar-more`. e2e (e) covers Settings at 1280 and More at 390×844 with real Tab/Escape, asserting `activeElement` is the trigger and never BODY.
7. **Phone:** the dialog fits at 390×844 with no horizontal overflow (`scrollWidth - clientWidth === 0`). Added to AC-P3-T03-6 and the e2e.
8. **Palette:** alpha tokens (dark `--border`) keep their alpha as `rgba()`. Unit test: fallback when `getContext` returns null. Light and dark exports differ in at least background, card and text colours (e2e d).
9. **Perf:** also log the GitLab SVG file size (MB) in the handoff. Main-thread generation is fine; record > 3 s as a known issue and don't optimise.
