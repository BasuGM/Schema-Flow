# P3-T06 — Session restore

## Context

Next task per the ROADMAP Now block (P3-T05 Verified in round 19). Backlog: QA-018 → P3-T07, QA-027…029 → P3-T08, QA-031…033 → BB-P3. None of them block this task. P3-T06 doesn't touch the inspector focus or the import dialog's file label, so P3-T08 stays separate.

Today a reload always shows the e-commerce sample, or the `?sample=` URL ([use-sample-loader.ts](src/components/workspace/use-sample-loader.ts)). The viewport is saved per fingerprint but never restored (ADR-025: "restoring belongs to P3-T06"). **Outcome:** a reload brings back the last imported schema, its pan and zoom, and the selected table with its inspector tab. A "Clear saved data…" item wipes everything this app stores on the device.

User decisions (plan review Q&A):

- **Storage:** IndexedDB, re-parse on restore. Store the source text, the format and the name; re-parse through the existing lazy parsers. Issues and source excerpts come back, and parser fixes apply.
- **Restore scope:** viewport plus selection (selected table and inspector tab). New imports still fit the view.
- **Privacy:** on by default, with "Clear saved data…" in Settings and More (confirm first). The README says what is stored locally.

## Behaviour (rules)

1. **URL `?sample=…` wins.** It loads that sample, as today, and doesn't read or change the saved session. Plain `/` restores the saved session if there is one; otherwise it loads the default e-commerce sample.
2. **What a session is.** It is the last *import*, not a sample. Import → save `{ v: 1, text, format, name, savedAt }` to IndexedDB (`schemaflow` db, `session` store, key `current`). `format` is the resolved choice (the parsed dialect or `"prisma"`), so a restore never re-detects differently.
3. **Restore flow** (`/`, nothing loaded):
   - The canvas shows a busy state, "Restoring <name>…" (`canvas-restoring`, `role="status"`).
   - Then `loadParsers()` → `afterNextPaint()` → `parseSchemaText(text, { format, name })`.
   - Then the same apply path as an import. Errors open the issues panel. The table selection and inspector tab come back if that table still exists, and the saved viewport is used instead of fitting the view.
   - **Fallback to the default sample:** if the IndexedDB read fails, takes longer than 2 s, the record is invalid, or the parse returns no schema. An invalid record or a failed parse is also deleted.
4. **Race guard.** Restore captures `schema-store.revision` when it starts. If the user imports or loads anything before restore finishes, the restore result is dropped.
5. **Viewport.** The layout store gets a one-shot `pendingViewport`, set only by restore. While it is set, `SchemaCanvas` mounts with `defaultViewport={viewport}` (zoom clamped to [0.05, 2]) and without `fitView`, then clears it. Imports, samples and Layout keep fitting the view as today. "Reset view" still fits.
6. **Selection.** `selectedTableId` and `inspectorTab` are saved to localStorage under `schemaflow:session-ui:v1` as `{ fingerprint, selectedTableId, inspectorTab }`:
   - Debounced at 300 ms, through a `ui-store` subscription, and flushed on `pagehide`.
   - Saved only while the current schema is the restored or imported session; never for samples.
   - Applied only when the fingerprint matches.
7. **Clear saved data…** sits in Settings (`settings-clear-data`) and More (`more-clear-data`) and opens a confirm dialog (`clear-data-dialog`, Confirm button `clear-data-confirm`). The dialog says that the last schema, the saved layouts and the preferences are stored only on this device, and that clearing them loads the sample.
   - Confirm: discard pending layout saves, clear the layouts, prefs, session-ui and the IndexedDB session, reset the in-memory layouts, load the default sample (fit view), and announce "Saved data cleared" in a polite live region.
   - Focus returns to the toolbar button the dialog was opened from.
8. **Never crashes.** Every IndexedDB and localStorage access is try/catch with a timeout. Blocked storage means the app works as it does today, without restore.
9. **Multi-tab:** last write wins (same as ADR-025).

## Workstream A — storage and restore logic

- `src/lib/session-db.ts`: a tiny raw IndexedDB wrapper with `getRecord` / `putRecord` / `deleteRecord`. Promise-based, never rejects (`null` / `"failed"`), with a 2 s timeout. The backend is injectable through `setSessionBackend()` for tests. No dependency: jsdom has no IndexedDB, so unit tests use an in-memory fake in `src/test/fake-session-backend.ts`.
- `src/stores/session-persistence.ts` (pure aside from storage):
  - `saveSession(record)`.
  - `loadSession()`: validates `v`, string `text` ≤ `MAX_IMPORT_BYTES`, known `format` and `name`.
  - `clearSession()`, plus the session-ui read and write with validation.
  - `clearAllSavedData()`, which reuses `clearSavedLayouts` / `discardPendingSaves` from [layout-persistence.ts](src/stores/layout-persistence.ts) and `PREFS_KEY` from [ui-store.ts](src/stores/ui-store.ts).
- `layout-store`: add `pendingViewport` and `takePendingViewport()`, plus `resetAll()` for Clear.
- `applyImportedSchema(schema, sourceText?, session?)` in [apply-import.ts](src/components/import/apply-import.ts): when `session` is given, also call `saveSession`. [import-dialog.tsx](src/components/import/import-dialog.tsx) passes `{ format: resolved, name }`. Restore reuses the same function without re-saving.
- `use-sample-loader.ts` → `use-session-restore.ts`, which implements rules 1–4. Keep `createSample` / `parseSampleRequest` as they are.

## Workstream B — UI

- `SchemaCanvas` gets `defaultViewport` and a conditional `fitView` (rule 5). It also gets the `canvas-restoring` busy text in place of "Loading schema…" while a restore runs. The restore status lives in `schema-store` as `restoring: { name } | null`.
- Selection sync hook (rule 6), mounted in `Workspace`.
- A `ClearDataItem` used by [settings-menu.tsx](src/components/workspace/settings-menu.tsx) and [more-menu.tsx](src/components/workspace/more-menu.tsx), plus a `ClearDataDialog` built on the existing shadcn Dialog. It returns focus like the export dialog does (`returnFocus` test id in `ui-store`).

## Amendments (user, plan review)

1. **Clear is final.**
   - On Confirm, also cancel the session-ui debounce and its pagehide flush.
   - Ignore or undo any `saveSession` put still in flight: keep a "cleared" generation counter and check it before every write. If a put lands after a clear, delete it.
   - Test: select a table, Clear within 300 ms, wait, reload. Expect the sample, no `schemaflow:session-ui:v1` key and no IndexedDB record.
   - **Other tabs:** post `{ type: "cleared" }` on `BroadcastChannel("schemaflow")` (no dependency). Other tabs then stop saving the session, session-ui and layouts until their next import. If `BroadcastChannel` is unavailable, document the multi-tab limitation in the README and ADR-030.
2. **A reload shows what was on screen.**
   - The app has **no in-app sample loader**: only `?sample=` and the default sample (verified: `use-sample-loader.ts` is the only `createSample` call site). ADR-030 says so. The one in-app path to the sample is Clear saved data, which clears the session.
   - A pasted SQL or Prisma schema counts as an import and is saved like a file.
3. **Phone (< md).**
   - Restore the selection (the node is highlighted) but don't auto-open the inspector sheet.
   - Keep the restored inspector tab pending and apply it only when the user opens the inspector.
   - Desktop restores both.
   - e2e at 390: after a reload the canvas is visible, with no sheet covering it.
4. **Blocked storage e2e** (like P3-T01), using `addInitScript`:
   - (a) `indexedDB.open` throws.
   - (b) `indexedDB.open` never resolves (hits the 2 s timeout).
   - Both cases: the sample is shown, there are no console errors, import still works, and a reload shows the sample.
5. **Restore never steals focus.**
   - After a restore, `document.activeElement` is `BODY` or wherever it was.
   - The "Restoring …" status is announced once and then removed.
6. **Warnings on restore.**
   - The issues panel follows the import rule.
   - Restore doesn't announce "Imported …" live text or toasts as if it were a new import (`applyImportedSchema` gets a `restored` flag).
7. **Handoff:** add a step listing the record and keys Cowork can inspect: the IndexedDB `schemaflow` → `session` → `current` fields (`v`, `text`, `format`, `name`, `savedAt`) and the localStorage keys.
