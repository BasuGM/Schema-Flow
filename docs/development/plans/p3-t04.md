## API (all pure, deterministic, never throw)

```ts
type GeneratedText = { text: string; warnings: string[] }   // warnings: grouped, human-readable, sorted
generateSql(schema, { dialect: SqlDialect }): GeneratedText
generatePrisma(schema): GeneratedText
generateMermaid(schema, { columns: "all" | "keys" }): GeneratedText
generateJson(schema): GeneratedText
generateSchemaText(schema, target): GeneratedText & { extension, mime }   // dispatcher for P3-T05
```
Output order follows `schema.tableOrder`; no timestamps; `\n` line endings, trailing newline.

## Workstream B — JSON and Mermaid

- `generateJson`: `{ format: "schemaflow-schema", version: 1, name, source, enums[], tables[], relationships[] }` with arrays in `tableOrder` order (not records), `issues` omitted, 2-space indent. Export-only in v1 (no importer); the shape is documented in ADR-028.

Implicit join tables are drawn as entities.
- Tests: golden strings on a small hand-built schema, ecommerce shape checks (every table is an entity, every relationship a line), a per-line regex validator for the output, sanitization of odd names.

## Workstream C — SQL (PostgreSQL / MySQL / SQLite)

Files: `src/generators/sql/{generate-sql,type-map,defaults,render-table}.ts`.

- **Source family:** `schema.source.dialect ?? "postgresql"` (samples and Prisma count as PostgreSQL unless the datasource says otherwise). Same dialect → `dataType.raw` as written. Different → map by `dataType.base` through a table (integer family, text family, boolean, numeric / decimal / float, date / time / timestamp(tz), uuid, json / jsonb, bytea / blob, serial → identity); unknown types pass through with an "approximated" warning.
- **Defaults:** `literal` as written; `function` mapped for the common ones (`now()` ↔ `CURRENT_TIMESTAMP`, uuid generators), else as written + warning; `expression` parenthesised; `autoincrement` → PostgreSQL `GENERATED BY DEFAULT AS IDENTITY`, MySQL `AUTO_INCREMENT`, SQLite `INTEGER PRIMARY KEY AUTOINCREMENT` (only for a single-column integer PK, otherwise dropped with a warning).
- **Layout:** PostgreSQL: `CREATE SCHEMA` for non-default schemas, `CREATE TYPE … AS ENUM`, `CREATE TABLE` (PK, UNIQUE, CHECK inline), `CREATE [UNIQUE] INDEX`, then `ALTER TABLE … ADD CONSTRAINT … FOREIGN KEY` for every relationship (so cycles and self-references are safe), then `COMMENT ON`. MySQL: same without types / schemas; inline `ENUM('a','b')`, inline `COMMENT '…'`, table `COMMENT='…'`, FKs via ALTER. SQLite: FKs inline in `CREATE TABLE` (no `ALTER ADD CONSTRAINT`), no comments (emitted as `--` lines).
- **Lossy cases (warnings, never failures):** enums on SQLite → `TEXT` + `CHECK (col IN (…))`; arrays on MySQL → `JSON`, on SQLite → `TEXT`; partitions folded into a table → dropped; schema-qualified tables on MySQL / SQLite → schema prefix dropped (duplicate names after dropping are reported); indexes with expressions are not representable (the parsers skip them too).
- Prisma-implicit join tables are emitted as ordinary tables.
- Tests, per dialect: golden snippets for each feature (composite PK / FK, 1:1, every default kind, checks, indexes, enum, array, comments, self-reference, cycle); **same-dialect fixed point** `canonical(parseSql(generateSql(s))) == canonical(s)` over ecommerce, `pgdump`, `edge-cases`, `shop.mysql`, `blog.sqlite`, sakila, mysqldump-180 (compare comments only where the parser reads them); **cross-dialect structure** (ecommerce → MySQL and SQLite → parse: same tables, columns, keys, relationships; types and defaults not compared) with the expected warnings asserted.

## Workstream D — Prisma

Files: `src/generators/prisma/{generate-prisma,field-types,relations}.ts`.

- Header: `generator client { provider = "prisma-client-js" }` and `datasource db { provider = <postgresql|mysql|sqlite from source dialect, default postgresql>  url = env("DATABASE_URL") }`.
- Models: name = PascalCase(table name) (no singularising), `@@map("table")` when different; field name = column name when a valid identifier, else a sanitised name + `@map`. Types: `dataType.base` → Prisma scalar (+ `@db.*` where the scalar's default native type differs, e.g. `varchar(255)` → `String @db.VarChar(255)`), arrays `[]`, unknown → `Unsupported("raw")`. Defaults: `autoincrement()`, `now()`, `uuid()`, `dbgenerated("…")`, literals; `@id` / `@@id`, `@unique` / `@@unique`, `@@index`.
- Relations: on the FK model `parent Parent @relation(fields:[…], references:[…], onDelete: Cascade …)`; on the parent a list field (`Child[]`, or `Child?` for one-to-one); `@relation("Name")` when two relations join the same pair of models; field names deduplicated deterministically. `origin: "prisma-implicit"` join tables (`_AToB`) are **folded back** into implicit m:n list fields on both sides and not emitted as models.
- Enums: `enum Name { A @map("a") }`, values mapped when not valid identifiers. A table without PK or unique key gets a warning (Prisma needs one) and a comment.
- Tests: golden snippets; **fixed point** `canonical(parsePrisma(generatePrisma(s))) == canonical(s)` over `blog.prisma` (implicit m:n), `shop.mysql.prisma`, `edge-cases.prisma`, `large-200.prisma`, and the SQL-origin ecommerce sample (names preserved via `@map`).

## Amendments (approved with changes)

1. **Cowork CLI:** `scripts/headless/generate.ts <fixture-path> <postgres|mysql|sqlite|prisma|mermaid|json>` prints the output to stdout and warnings to stderr, runnable with plain Node (22.21 here: type stripping is on by default; no new dependency). A small resolve hook (`scripts/headless/alias-hook.mjs`, registered with `--import`) maps `@/…` and extensionless relative imports to `src/**/*.ts(x)`; the header documents the exact command, e.g. `node --import ./scripts/headless/alias-hook.mjs scripts/headless/generate.ts tests/fixtures/sql/ecommerce.postgres.sql sqlite`. The input format is detected with `parseSchemaText` (SQL dialect auto, or Prisma). Everything the script imports must be type-stripping-safe (`import type` only for types, no enums or namespaces); if that blocks, escalate rather than add a dependency. Cowork runs it on fixtures, executes SQLite output in `sqlite3` (present on this machine; `mmdc` is not, so Mermaid rendering is Cowork's), and the handoff lists the exact commands. Status **Awaiting Cowork verification**.
2. **Escape every user string, a test for each** (shared fixture: a table / column / comment / enum value containing `'` `"` `` ` `` `\` newline `--` and `*/`):
   - SQL string literals (enum values, defaults, `COMMENT` text): `'` doubled; MySQL also doubles backslashes.
   - SQLite `-- comment` lines: every line of a multi-line comment is prefixed with `-- `, so a newline can't end the comment.
   - Prisma: `@map` / `@@map` / `dbgenerated` / `Unsupported` strings escape `\` and `"`; `///` doc comments never contain a raw newline.
   - Mermaid: quoted entity names, attribute comments and relationship labels have `"` and newlines removed or replaced.
3. **Cross-dialect traps** (warning + safe output, a test each):
   - MySQL: TEXT / BLOB columns used in a PK, UNIQUE, index or FK become `VARCHAR(255)` / `VARBINARY(255)` with a warning.
   - CHECK expressions and expression defaults copied as written cross-dialect: one "copied as written, may need editing" warning per table.
   - Index and constraint names deduplicated deterministically where the target needs uniqueness (PostgreSQL / SQLite index names are per schema / database), especially after a schema prefix is dropped.
   - Identifiers longer than 63 chars (PostgreSQL) / 64 (MySQL): warning.
4. **Round-trip honesty:** `canonicalSchema` exports one constant listing what it excludes (e.g. PostgreSQL comments, which the parser skips). A test enumerates the keys of `Schema`, `Table`, `Column`, `Relationship`, `EnumType` (from a populated sample object) and fails if a field is neither compared nor in the excluded list.
5. **SQLite execution:** when `node:sqlite` exists (Node ≥ 22.5), a test runs the generated SQLite DDL for ecommerce (from PostgreSQL) and `blog.sqlite` in an in-memory DB and checks the `sqlite_master` table count (and that `PRAGMA foreign_key_check` is clean); skipped with a message otherwise. No dependency.
6. **Degenerate inputs:** an empty schema and a schema with only a no-PK table: every target returns valid output (valid empty `erDiagram`, empty-but-valid JSON, SQL with just a header comment, Prisma header only) plus the Prisma "needs a unique key" warning; tests for each target.
