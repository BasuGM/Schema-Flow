## QA-039: the sheet stays open and the table is placed in the visible band above it
Everything goes through `revealTable` → `focusRequest` → `useCanvasCommands`, so one change in `src/components/canvas/use-canvas-commands.ts` fixes both the Issues and the Health sheets.

**Pure exported helpers, unit-tested in `use-canvas-commands.test.ts`:**
- `visibleCanvasHeight(h, coveredPx)` returns `max(0, h - coveredPx)`.
- `sheetCenterOffset(h, visibleH, zoom)` returns `(h - visibleH) / 2 / zoom`. It is 0 when nothing is covered and a positive (downward) flow-y shift when the sheet is open.
- `tallNodeTargetY(nodeY, visibleH, zoom, h)`: when `nodeHeight * zoom > visibleH`, it returns the centre y that puts the node top about 16 px below the pane top. That works out to `nodeY - 16/zoom + h/2/zoom`.

**Measuring the overlap at reveal time** (non-pure part of the effect):
- `covered = max(0, paneRect.bottom - sheetRect.top)`. `paneRect` comes from the React Flow pane (`flowStore.getState().domNode` getBoundingClientRect). `sheetRect` comes from `[data-testid="issues-sheet"]`.
- When the sheet element is not in the DOM but `issuesSheetOpen()` is true, the fallback is `covered = h * SHEET_HEIGHT_PERCENT/100`. Otherwise `covered = 0`.

**Centre mode:**
- Compute the target zoom first.
- If `height * zoom > visibleH` (a tall table), use the top-aligned target.
- Otherwise use the target y plus `sheetCenterOffset(h, visibleH, zoom)`.

**Ensure-visible mode:**
- The visibility check uses `visibleH` as the bottom bound.
- When it pans, it uses the same target rule (tall → top-aligned, otherwise shifted), at the current zoom.

Desktop and the docked panel are unchanged, because there nothing covers the pane (`covered = 0`).
