# P4-T04 — Keyboard shortcuts & command palette extensions

## Context

## Acceptance criteria (draft)
1. ⌘K with an empty query lists commands; typing "lay" shows Layout first; `>` shows commands only; Enter runs it.
2. Commands for Layout, Reset view, Export, Export image, Import, Health, Path finder, panels, minimap, theme, areas, shortcuts, clear data all work; disabled ones are marked and do nothing.
3. Single keys F, L, [, ], H, E, I, ? work on the canvas and do nothing while typing in an input or with a dialog/menu open, or with Ctrl/Meta/Alt.
4. `?` (and Settings/More → Keyboard shortcuts) opens a dialog listing every shortcut; Escape closes it, focus returns.
5. Existing search (tables/columns, ⌘K, `/`, Escape) behaves as before (search.spec green).
6. Area commands on saas-300 hide/show areas exactly like the Areas list.
7. Keyboard and screen reader: command rows are options in the same listbox with labels; visible focus.
8. 390×844: toolbar-width PASS light/dark; palette and help dialog fit without horizontal overflow.

## Cowork amendments (plan review at fca073f, APPROVED with amendments) — these override the above
1. Key matching: allow Shift (so `?` = Shift+/ works; letters matched case-insensitively via `e.key`,
   CapsLock fine); Ctrl/Meta/Alt still ignored; ignore `e.repeat`. Unit tests: Shift+?, uppercase L,
   CapsLock, repeat.
2. `/` matcher must not catch Shift+/ → `?` opens help, not search (US layout). README notes `[`/`]`
   may need AltGr on some layouts.
3. Phone sheets (`side-sheet.tsx`, issues sheet; no dialog role): single keys still work with a sheet
   open, but E/I/? first close the sheet. AC + test.
4. Letters with focus on a button/checkbox/tab still fire (acceptable). `[`/`]` while focus is inside
   the panel being collapsed moves focus to the matching toolbar toggle (fallback: canvas pane), never
   `<body>`. Test.
5. Area commands ("Show only / Hide area X") appear only for a typed query matching the area name, never
   in the empty-query list (GitLab: 79 areas). "Show all areas" stays in the list.
6. Focus return: after a command opens another dialog (Export, Import, Shortcuts, Clear data), closing
   it returns focus to the element focused before ⌘K; same for non-dialog commands (Layout, Reset view,
   theme). Tests for both.
7. `aria-keyshortcuts` on toolbar buttons that have a key. Disabled commands stay as `aria-disabled`
   options that Enter skips; status count includes them correctly.
8. Help dialog renders exactly the `SHORTCUTS` table (no hand-written copy); ⌘ vs Ctrl per platform;
   fits 390 without horizontal scroll.
9. Handoff lists: expected empty-query command list (labels + disabled state) for ecommerce with nothing
   selected and saas-300 with a table selected; expected top result for "lay", "exp", "theme", "bill"
   (saas-300); ADR-016 bundle delta in bytes.
