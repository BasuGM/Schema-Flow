   `src/stores/session-persistence.ts`. `activePath` is not persisted: after a reload the Path tab

2. **Escape**: in `path-target-input`, Escape clears the query only (the path stays; the global

   path and selection stay; a second Escape clears them. AC + e2e match this.
3. **Tie-break**: BFS with neighbours visited in (`tableOrder` index, relationship id) order; the
   first-discovered parent wins. Unit test with two equal-length routes asserting the exact tables.
4. **Hop display**: the FK is always rendered `fkTable.cols → refTable.cols` (arrow = FK
   direction); the walk direction is text: "references" / "referenced by". One path in a test has
   both.
5. **Canvas edge cases**: on-path edges stay visible and highlighted in the zoomed-out overview
   (`canvasZoomedOut`) and in the keys/header collapse modes; with parallel FKs only the chosen
   relationship's edge has `data-on-path`. Hovering or clicking (pinning) an edge does not drop the
   path.
6. **Clear** restores the previous focus state (neighbourhood dimming of the selected table at the
   current depth), not "nothing dimmed". Test it.
7. **Picker**: schema-qualified names via `displayTableName` (saas-300 has two `t001_wide`); empty
   query lists the first 50 by `tableOrder` with "Type to narrow (N tables)"; ArrowUp/Down/Enter
   with visible focus.
8. **Phone**: the 4-tab inspector tablist fits at 390 px (no horizontal overflow, labels not
   clipped); Show on canvas closes the sheet and fits the path with `fitPadding`; toolbar-width PASS.
9. **Handoff recount table**: at least 4 saas-300 pairs (one ≥ 4 hops, one through a join table if
   there is one, one unreachable orphan pair) with expected tables in order and hop counts,
   produced by a unit test that prints them.
10. **Image export**: the export renders from the schema (`diagram-svg.ts`) and ignores `focusSet`,
    as with neighbourhood dimming, so the path dim is **not** exported. One AC line plus a unit or
    e2e assertion that an export with an active path has no dimmed elements.

## Context

ROADMAP Now → Next is P4-T02 "Path finder between tables" (title only, no spec). P4-T07 is Verified;
QA Backlog has 0 open items. The goal: pick two tables and see how they connect (the join chain) —
listed as hops with the FK columns, and highlighted on the canvas with everything else dimmed.
Scope: ≤ ~300 tables, so a plain BFS is instant; no perf work.

Design decisions (ADR-035):
- **Undirected shortest path** (fewest hops) over relationships, either FK direction (a join works
  both ways). One path, deterministic tie-break (`tableOrder`, then relationship id). No
  "all paths" / max-hop setting.
- **UI lives in the inspector as a 4th tab "Path"**: From = the selected table, To = a table
  picker. Works the same on desktop and in the phone inspector sheet; no new toolbar button
  (the phone toolbar width budget stays untouched).
- **The active path is independent of the selection**: clicking path tables to inspect them keeps
  the highlight. It is cleared by its Clear button, Escape (`clearSelection`), a new schema, or
  finding another path.

## A — `src/domain/schema/path.ts` (pure TS)

```ts
export interface PathHop {
  from: TableId;          // table we walk from
  to: TableId;            // next table
  relationshipId: RelationshipId;
  direction: "references" | "referenced-by"; // from holds the FK, or to holds it
}
export interface TablePath { tables: TableId[]; hops: PathHop[] } // tables.length = hops.length + 1
export function findPath(schema: Schema, from: TableId, to: TableId): TablePath | null;
```

- BFS from `from`; neighbours built once per schema like `getAdjacency` (new WeakMap-cached
  relationship-level adjacency: `TableId → {other, relationshipId, direction}[]`, sorted by
  `tableOrder` index then relationship id for determinism). Self-references skipped.
- `from === to` → `{ tables: [from], hops: [] }`; unknown table or unreachable → `null`.
- Tests `path.test.ts`: direct FK both directions; 2–3 hop chain; shortest wins over longer;
  deterministic tie; unreachable → null; same table; self-reference ignored; parallel FKs between
  the same pair (picks lowest id); implicit Prisma join table traversed; a run over
  `tests/fixtures/synthetic/saas-300.postgres.sql` (a known pair → expected hop count).
