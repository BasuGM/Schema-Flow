**Context.** SchemaFlow is a browser-only database schema explorer that turns a schema into an
interactive entity-relationship diagram. This batch adds `parsePrisma(text)`, which turns a
`schema.prisma` file into the same normalized schema model as SQL import, returning
`ImportResult { ok, schema?, issues[] }`. There is no import UI yet (P2-T05), so Prisma import is
verified through tests.

- **Parser choice (user decision, ADR-013):** the planned `@mrleebo/prisma-ast` was not used. At
  import time it searches the filesystem for a config file and imports Node's `os`, so it doesn't
  bundle for the browser without shims. It also fails the whole file on the first syntax error.
  We wrote a small, dependency-free, tolerant parser instead, like the SQL one.

**What changed**

- **QA-009:** the tokenizer treats U+FEFF as whitespace anywhere, never as part of an identifier.
  It was previously skipped only at the start of the file.
- **Escape:** a new `clearSelection()` action in `ui-store` clears the selected table and unpins a
  clicked edge (label hidden, selected style removed). This works whether or not a table is
  selected. Escape still does nothing inside text inputs and open menus.
  - Found during self-check: edges are not focusable, so after clicking an edge, keys come from
    `<body>` and never reached the old handler on the workspace root.
  - The Escape listener is now on `document` (`use-escape-to-clear.ts`), and the test fires
    Escape from `<body>`, as a browser does.
- **P2-T04 (`src/parsers/prisma/`):**
  - lexer (line breaks are tokens; `///` comments kept);
  - block parser (one member per line, multi-line `(…)` arguments supported; bad lines skipped
    with a line-numbered warning);
  - mapping:
    - `@map`/`@@map`/`@@schema`;
    - relations resolved to mapped column names with `onDelete`/`onUpdate`/`map`;
    - `@id`/`@@id`, `@unique`/`@@unique`, `@@index`/`@@fulltext`;
    - `@default` kinds;
    - native `@db.*` types;
    - enums;
    - implicit many-to-many join tables `_AToB`.
  - Prisma scalars without `@db.*` keep their Prisma names (`String`, `DateTime`).
  - **Size:** 926 lines excluding tests (≈820 code lines). This is **larger than the 350–450 lines
    estimated** when this option was proposed. `src/parsers` is now 2,324 lines in total.

**Edge cases covered by tests:**

- Multi-line `@@index([...])`.
- An unclosed `@default(` doesn't swallow the following fields.
- Leading and trailing `///` comments.
- `Unsupported("point")?`.
- `@db.UnsignedInt` → `int unsigned`.
- Named relations (`@relation("Replies", …)`).
- An empty file, and a file with no models.
- 360 seeded truncations/corruptions plus 400 random inputs never throw.

**Performance:** a 500-model schema (0.63 MiB) parses in **57–118 ms** (4 runs, Node, M1). The test
asserts < 1.5 s.

**Known limitations:**

- No import UI yet (P2-T05).
- Views are skipped.
- MongoDB composite `type`s are shown by name only.
- Prisma scalar types without `@db.*` are shown as Prisma names, not provider SQL types.
- Implicit many-to-many needs a single-field `@id` on both models (otherwise skipped with a
  warning).
- `relationMode = "prisma"` is ignored: relations are drawn as foreign keys even though Prisma
  creates no database constraints in that mode.
