**Task:** P3-T03, image export (PNG / SVG), ADR-027. Nothing here is independently verified.

**Summary:** Settings (or More on a phone) → "Export image…" opens a dialog: PNG or SVG of the whole
diagram, theme Current / Light / Dark, PNG scale 1× / 2×. The image is drawn by our own SVG renderer
(no `html-to-image`; the canvas virtualizes large schemas, so a DOM snapshot would miss tables).

**Pushed commits:** `afc24c5` SVG generator, raster sizing, shared `edgePath` · `6f27a3c` adapters,
dialog, menu items · `cc51832` e2e spec + perf script · docs commit (the one after `cc51832`;
`origin/main` = local `HEAD`).

**Steps → expected**

1. **e2e.** `npm run e2e` on a served normal build: 157 passed, 0 failed, 20 skipped (Claude Code's
   run). New: `export.spec.ts` (8 tests). Record your own counts.
2. **Open.** Settings → "Export image…": dialog with PNG, Current and 2× selected; a size line
   ("N tables · W × H px") and a PNG line. With no tables the item is disabled.
3. **SVG.** Choose SVG (scale becomes disabled) → Download: `<schema-name>.svg`; open it in a browser:
   every table and relationship, at the canvas positions, in the tables' collapse modes.
4. **PNG.** PNG 1× → Download: image size equals the size line; 2× is twice that.
5. **Themes.** Light and Dark exports differ (background, cards, text) whichever theme the app is in.
6. **Collapse.** Settings → All tables → Keys only, export SVG: only PK / FK rows.
7. **Odd names.** Import `CREATE TABLE "a<b&c" (id int PRIMARY KEY);`, export both formats: the name
   shows as `a<b&c`, the SVG opens, the PNG is valid.
8. **Large schema.** Import GitLab `structure.sql` (992 tables): the dialog notes "PNG reduced to
   0.0675×…"; SVG downloads at full detail; a busy "Exporting…" state shows; the page stays usable.
9. **Focus / keyboard.** Escape or Cancel returns focus to the Settings button (More at 390 px), not
   the page. Tab reaches every radio; a ring shows on the label. No horizontal overflow at 390 px.
