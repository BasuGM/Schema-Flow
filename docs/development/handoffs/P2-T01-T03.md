### Claude Cowork Verification Handoff

**Tasks:** P2-T01 (SQL tokenizer, splitter, format detection), P2-T02 (PostgreSQL DDL import),
P2-T03 (MySQL and SQLite import). This is the Phase 2 **import core, pure logic only**.

**Context.** SchemaFlow is a browser-only database schema explorer that turns a schema into an
interactive entity-relationship diagram. This batch adds the SQL import engine: `parseSql(text)`
turns SQL DDL into SchemaFlow's normalized schema model and returns
`ImportResult { ok, schema?, issues[] }`.

- **No UI change, so there is nothing new to see in the browser.** The Import button stays
  disabled until P2-T05 (import dialog).
- SQL is only tokenized, never executed.
- **Parser choice:** `node-sql-parser` was evaluated and rejected. Its PostgreSQL build fails
  whole `CREATE TABLE` statements on enum-typed columns, `GENERATED ALWAYS AS IDENTITY`, and
  `REFERENCES t` without columns. With the user's approval we wrote a small, dependency-free,
  tolerant DDL parser instead (ARCHITECTURE ADR-012).

**Implementation summary.**

- `src/parsers/sql/tokenizer.ts`: dialect-aware tokenizer (strings, quoted identifiers, nested
  comments, `$tag$` bodies).
- `split.ts`: splits on top-level `;` only.
- `token-stream.ts`: cursor shared by the statement parsers.
- `parse-column.ts`, `parse-default.ts`, `references.ts`, `parse-table-constraint.ts`,
  `parse-statements.ts`: CREATE TABLE / ALTER TABLE / CREATE INDEX / CREATE TYPE ENUM.
- `parse-sql.ts`: the entry point. Irrelevant statements (SET, OWNER TO, GRANT, COMMENT ON,
  sequences, functions/triggers, …) become **one** summary warning; relevant-but-unhandled
  statements get line-numbered warnings.
- `src/parsers/detect-format.ts`: SQL / Prisma / unknown detection, plus a dialect guess.
- `src/parsers/index.ts`: public API.
- Domain change: the duplicate-table error now says "(names are matched case-insensitively)".
- `src/samples/synthetic.ts` exports its PRNG for seeded tests.
- **Size:** `src/parsers` is **1,381 lines** excluding tests (≈1,190 code lines without
  comments and blank lines; Prettier puts many lists one item per line). **This is beyond the
  ~1k lines estimated in the plan.** Tests add 642 lines.

**Edge cases covered by tests:**

- Enum columns that are schema-qualified or quoted.
- Multi-word types (`timestamp(3) with time zone`, `double precision`).
- MySQL `name(20)` index prefixes vs `lower(name)` expressions.
- SQLite columns without a type.
- `ALTER COLUMN … SET DEFAULT nextval(...)` and `ADD GENERATED … AS IDENTITY`.
- Empty input, and input with no tables.
- Unterminated strings, comments and dollar quotes.
- 600 seeded truncations or corruptions of the fixtures plus 400 random inputs: `parseSql` never
  throws (the suite runs in about 0.5 s against a 2 s budget).

**Performance:** a generated ~1 MB (0.96 MiB) DDL file with 500 tables parses in **99–144 ms**
(3 warm runs, Node, M1). The test asserts < 1.5 s.

**Known limitations:**

- No UI yet (P2-T05).
- `COPY … FROM stdin` data blocks are not supported (use `pg_dump -s`).
- MySQL `DELIMITER` blocks are reported, not parsed.
- Expression and partial-index semantics are not modelled: expression indexes are skipped, and a
  `WHERE` clause on a unique index is ignored, so it still counts as unique.
- Names are matched case-insensitively, so `"UserID"` and `userid` collide (documented).
- Prisma import is P2-T04.
